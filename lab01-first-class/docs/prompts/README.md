# Журнал применения ИИ

## Реконструированный сценарий работы

**Дата:** 08.10.2026  
**Инструмент:** OpenAI Codex

Приведённые ниже промпты реконструируют основные этапы работы. Они не являются дословной перепиской с пользователем.

### 1. Анализ методических требований

**Промпт:**

> Проанализируй методические указания к лабораторной работе №1. Выдели обязательные требования к классу `Book`, точке входа, отчёту и журналу применения ИИ. Индивидуальные варианты не учитывай.

**Результат:** выделены поля `id`, `title`, `author`, `year`, требования к getter/setter, валидации, `getDescription()` и созданию трёх объектов.

**Критический анализ и изменения:** требования сверены с актуальным `lab1.md`. Индивидуальное задание исключено, но все восемь контрольных вопросов и общая практическая часть сохранены.

### 2. Проектирование структуры проекта

**Промпт:**

> Предложи структуру Maven-проекта для лабораторной №1 на Java 17 с пакетами исходного кода, тестами, отчётом и журналом ИИ.

**Результат:** предложены стандартные каталоги `src/main/java`, `src/test/java`, `docs/prompts` и файл `pom.xml`.

**Критический анализ и изменения:** структура соответствует соглашениям Maven. Использован пакет `com.university.lab01`, а результаты сборки `target` добавлены в `.gitignore`.

### 3. Создание класса `Book`

**Промпт:**

> Создай класс `Book` с приватными полями `id`, `title`, `author` и `year`. Добавь конструктор, getter и setter для каждого поля, соблюдая Java Code Conventions.

**Результат:** подготовлен класс с инкапсулированными полями и публичными методами доступа.

**Критический анализ и изменения:** конструктор направляет значения через setter-методы, поэтому правила проверки не дублируются. Все публичные элементы дополнены Javadoc.

### 4. Добавление валидации

**Промпт:**

> Добавь проверку данных: название и автор не должны быть `null` или пустыми, год должен находиться от 0 до текущего года. При ошибке выбрасывай `IllegalArgumentException`.

**Результат:** добавлены проверки строк через `isBlank()` и динамическая верхняя граница года через `Year.now()`.

**Критический анализ и изменения:** фиксированный текущий год отклонён как быстро устаревающее решение. Дополнительно введена проверка `id > 0`; глобальная уникальность идентификатора не реализована, поскольку класс не управляет хранилищем книг.

### 5. Форматирование описания книги

**Промпт:**

> Реализуй `getDescription()` в формате `"Название" — Автор (год)` и переопредели `toString()`, не дублируя форматирование.

**Результат:** описание формируется методом `String.formatted()`, а `toString()` делегирует вызов `getDescription()`.

**Критический анализ и изменения:** точный формат сопоставлен с примером методички. Делегирование устраняет риск расхождения двух строковых представлений.

### 6. Создание точки входа

**Промпт:**

> Создай класс `Main`, сформируй три объекта `Book` и выведи нумерованный список их описаний по образцу из задания.

**Результат:** создан массив из трёх книг и цикл вывода с заголовком `=== Список книг ===`.

**Критический анализ и изменения:** выбран массив, поскольку количество объектов фиксировано и коллекция здесь не даёт преимуществ. Вывод проверен на совпадение с требуемым форматом.

### 7. Подготовка модульных тестов

**Промпт:**

> Напиши JUnit 5-тесты для класса `Book`: проверь getter/setter, формат описания и отклонение некорректных идентификатора, названия, автора и года.

**Результат:** создано семь тестов, покрывающих корректные значения и основные ошибочные случаи.

**Критический анализ и изменения:** отдельно проверены `null`, строка из пробелов, отрицательный год и год позднее текущего. Тест года вычисляет границу динамически и не устаревает.

### 8. Проверка качества кода

**Промпт:**

> Проведи ревью исходного кода: проверь инкапсуляцию, отсутствие дублирования и магических значений, длину методов, именование и полноту Javadoc.

**Результат:** подтверждены приватность полей, компактность методов и единое место валидации.

**Критический анализ и изменения:** существенных архитектурных усложнений не добавлено. Для небольшой учебной модели отдельные слои `service` и `repository` признаны избыточными.

### 9. Подготовка отчёта

**Промпт:**

**Результат:** создан `README.md` с полной структурой отчёта и данными студента Саврико Ильи, группа ИИ21/1.

**Промпт:**
