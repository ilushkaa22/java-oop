# Журнал применения ИИ — лабораторная работа №2

Это **реконструированный сценарий работы** из десяти последовательных промптов. Формулировки отражают выполненные этапы, не являются дословной перепиской и не приписываются пользователю как реальные сообщения.

Фактически использован OpenAI Codex; для проверки применялись просмотр методички, файловые и терминальные инструменты, Maven, JUnit, Java и javap. YandexGPT и GigaChat не использовались.

**Результат:** Изучены обязательная часть, методические указания и восемь вопросов.

**Критический анализ:** Обнаружено противоречие между требованиями конструкторов и примером ИИ-промпта. За основу взята обязательная часть.

**Внесённые изменения и причины:** Сохранено id=0 у конструкторов без ID; автоматическое назначение запланировано в фабрике.

### 3. Конструкторы

**Дата:** 09.10.2026.  
**Инструмент:** OpenAI Codex.

**Промпт:**

> Добавь четыре конструктора Book, организуй делегирование через this(...), сохрани единое место проверки данных.

**Результат:** Добавлены конструкторы без параметров, со всеми параметрами, без ID и с названием и автором.

**Критический анализ:** Значения по умолчанию сверены с заданием; отрицательный ID остаётся ошибкой. Дублирование валидации не требуется.

**Внесённые изменения и причины:** Проверка ID изменена на id>=0, дополнительные конструкторы вызывают основной.

### 4. Счётчик

**Дата:** 09.10.2026.  
**Инструмент:** OpenAI Codex.

**Промпт:**

> Реализуй общий счётчик успешно созданных объектов и статический getter. Исключения не должны увеличивать счётчик.

**Результат:** Добавлены static counter и getCounter().

**Критический анализ:** Инкремент в начале конструктора ошибочно учитывал бы неудачные попытки создания. При делегировании нельзя считать объект несколько раз.

**Внесённые изменения и причины:** counter++ размещён после всех проверок только в основном конструкторе.

### 5. Фабрика

**Дата:** 09.10.2026.  
**Инструмент:** OpenAI Codex.

**Промпт:**

> Добавь createBook(title, author, year) с возрастающим ID. Объясни отличие номера создания от ручного ID.

**Результат:** Фабрика передаёт counter+1 в основной конструктор.

**Критический анализ:** Дополнительный инкремент в фабрике дал бы двойной подсчёт. Ручные ID могут совпадать с фабричными; многопоточность и постоянное хранение не реализуются.

**Внесённые изменения и причины:** Инкремент оставлен только в конструкторе; ограничения ID описаны в Javadoc и отчёте.
